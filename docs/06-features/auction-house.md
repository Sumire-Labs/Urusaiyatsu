## 確定仕様

- `/auction` を追加し、総合レベル7以上で利用可能にする。
- 任意のインベントリアイテムを、同一 `id`・`meta` のスタックから出品できる。装備中の品物は外してから出品する。
- 個数・価格は1以上の整数。価格は出品全体の総額で、購入は一括のみ。
- 手数料は出品確定時に徴収する。

| 出品期間 | 手数料 |
|---|---:|
| 6時間 | 個数×1 |
| 1日 | 個数×2 |
| 3日 | 個数×4 |

- 売却代金は全額を出品者に支払う。手動取り消し・期限切れでは品物を返却し、手数料は返金しない。
- 全サーバー共通の出品一覧とする。自己購入は禁止し、出品者名にはゲーム内ニックネームを使う。

## データと取引処理

- `auction.json` はリスト形式とし、各出品に次の5項目を保存する。

  `id: int`、`seller_id: int`、`item: {id, count, meta}`、`price: int`、`expires_at: int`

- 出品IDはUUID由来の正整数とする。購入・取り消し・期限切れ処理後は出品を削除する。
- コア層に出品・購入・取り消し・期限切れ返却の処理を集約する。品物の `meta` は深いコピーで保持する。
- 出品確定時に、選択した `id`・`meta` のスタックを再検索し、数量・所持金・レベルを再確認する。確認画面までは品物や手数料を消費しない。
- 購入時に出品の存在・期限・購入者の残高・自己購入でないことを再確認する。検証から保存まで `await` を挟まず、二重購入や取り消しとの競合を防ぐ。
- 起動時と毎秒の背景処理で期限切れを返却する。画面操作時にも期限を確認し、`現在時刻 >= expires_at` なら購入できない。
- `/admin_transit` では出品者IDも移行し、返却先・代金受取先を引き継ぐ。

## Discord画面

- Cogを登録し、UIを `views/`、入力Modalを `modals/` に配置する。各パッケージから必要な入口を再公開する。
- 一覧は新しい出品順、1ページ25件。Select・前後ページ・更新・「出品」ボタンを設ける。空一覧でも出品操作は可能にする。
- 詳細には品名・数量・`meta`・総額・出品者名・終了までの時間を表示する。他人の出品には「買う」、自分の出品には「取り消す」を表示する。
- 出品メニューには自分の出品をEmbedでページ表示し、「出品する」から次の順で進む。

  インベントリ選択 → 個数・総額のModal → 期間選択 → 内容・手数料の確認 → 確定

- 同じアイテムでも `meta` が異なるスタックは別々に表示する。確認画面には期間・総額・手数料を明示する。
- 全画面をephemeralとし、起動したユーザーだけが操作できる。View・Modalは180秒で失効させ、共通のタイムアウト処理を使う。
- 在庫不足・残高不足・売却済み・期限切れ・不正入力は、状態を変更せず具体的なエラーを返す。保存完了後に成功を通知する。

## 永続化・運用

- `user.json` と `auction.json` をまたぐ取引には、両方の更新後スナップショットを持つ復旧ジャーナルを使う。
- 保存を既存の保存ロックで直列化し、ジャーナル確定 → 両ファイルの原子的置換 → ジャーナル削除の順で処理する。ファイルとディレクトリを同期する。
- 起動時は通常の状態読込より先にジャーナルを復旧する。ジャーナル確定前の失敗では取引を反映せず、確定後の保存失敗では停止して再起動時に復旧する。
- `auction.json` は初回のみ空リストで作成する。破損・不正な参照はログとバックアップを残して起動を中止し、空データで上書きしない。
- Dockerでは既存の永続ボリュームに出品・ジャーナルを保存する。既存ボリュームへの初期化、権限、シンボリックリンク、Git・Dockerの除外設定を追加する。

## 実装と運用の補足

- 状態ロックを取得してから、通常状態読込の前に `core/storage.py:recover` を実行する。ジャーナルはユーザーファイル実体と同じディレクトリの `auction-journal.json`。Dockerでは `/app/runtime/` に置く。
- `core/auction.py` の各操作はコピー上で検証・更新し、`core/storage.py:commit` が保存を完了してからメモリに反映する。出品、購入、取消、期限切れ一括返却、ユーザー移行でこの方式を共有する。
- 保存ロックは既存 `core/utils.py:_save_lock` と共有する。各ファイルの一時ファイルを flush/fsync → replace → ディレクトリfsyncする。ジャーナル削除後にもディレクトリfsyncする。
- ジャーナル確定前の失敗は元のメモリと通常ファイルを維持する。確定後の失敗は `SystemExit(1)` で終了し、通常の例外ログ処理で継続させない。再起動時は両スナップショットを再適用する。
- 返却は元の `id`・`meta` に一致するスタックに加算し、一致しなければ深いコピーを追加する。アイテムの既定metaは合成しない。
- 出品リストの配列末尾が最新出品。UUIDの数値順には依存しない。
- ViewとModalは180秒の期限と所有者を検査し、共通タイムアウトヘルパーで無効化する。確定・購入・取消の完了時にはViewを停止し、二重クリックを拒否する。
- 一覧・戻る・中止・ページ送りなど、同じメッセージの画面を置換する前に旧Viewを停止する。Modalを開いただけでは元のインベントリ画面を残し、有効な入力を送信して期間選択に進む時点で停止する。停止済みViewの遅延タイムアウトは新画面を編集しない。
- Discordの文字数上限に合わせ、一覧の選択肢説明と詳細metaの表示は切り詰める（保存データは全量保持）。
- 通常読込とジャーナル復旧で全ユーザーの取引関連フィールドと全在庫を検査する。出品が空でも不正なユーザースナップショットを復旧しない。重複JSONキー・非有限数値も拒否し、元データとバックアップを保持して停止する。
- `/admin_transit` は従来どおり移行先のプロフィールを移行元で置換する。移行元の出品者IDを移行先へ変更し、移行先に既にあった出品も移行先IDのまま引き継ぐ。同一IDへの移行は拒否する。
